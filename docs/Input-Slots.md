# Input-слоты (предметы игрока в меню)

**Input-слот** — ячейка меню, куда игрок кладёт **свой** предмет: заготовку для кузницы, ключ от кейса,
ингредиент для обмена. Дальше меню может его прочитать (`slot_matches`), изменить (`modify_slot`), забрать
(`clear_slot`) или отдать обратно (`give_slot`).

Слот становится input-слотом ровно от наличия ключа **`input:`** у элемента:

```yaml
items:
  '13':
    input:
      accept:
        - material: DIAMOND_SWORD
```

Всё остальное (`accept`, `max-amount`, `placeholder`, …) — необязательно.

!!! danger "Предмет игрока потерять нельзя"
    Содержимое input-слота возвращается владельцу при закрытии меню, выходе с сервера, смерти,
    `/am reload`, выключении плагина и **переживает краш сервера** — см.
    [Сохранность предметов](#сохранность-предметов). Это не «постарается вернуть», а инвариант плагина.

---

## Быстрый старт

Минимальный «сейф»: положил — забрал.

```yaml
type: chest
title: "&8» &bЯчейка"
rows: 3
commands: [cell]

items:
  '13':
    input:
      max-amount: 64
      placeholder:
        material: GRAY_STAINED_GLASS_PANE
        name: "&7Положи сюда предмет"
```

`accept:` не задан — слот принимает что угодно. `max-amount: 64` — в ячейку влезет целый стак.

## Полный пример — кузница

Игрок кладёт свой меч в слот `13`, держит в инвентаре золотой слиток и жмёт на молот (слот `11`). Слиток
списывается, бросается **ровно один** исход из таблицы весов `60/35/5`. Это ровно тот `menus/forge.yml`,
который плагин кладёт в `plugins/AlexMenus/menus/` при первом запуске (`/forge`, `/кузница`).

```yaml
type: chest
title: "&8» &6Кузница"
rows: 3
commands: [forge, кузница]
command-description: "Открыть кузницу (улучшение оружия)"

items:

  # --- Справка ------------------------------------------------------------
  '4':
    material: BOOK
    name: "&6&lКузница"
    lore:
      - "&7Положи меч в центр, держи в инвентаре"
      - "&7&fзолотой слиток &7и ударь молотом."
      - ""
      - "&a60%&7 — улучшение"
      - "&e35%&7 — слиток сгорел впустую"
      - "&c5%&7 — меч разрушен"

  # --- Кнопка-катализатор -------------------------------------------------
  # ОБЫЧНЫЙ (не input) элемент: именно на нём живут click-requirement и clicks.
  '11':
    material: GOLD_INGOT
    name: "&6Ковать"
    lore:
      - "&7Цена: &f1 золотой слиток &7из инвентаря"
    click-requirement:
      require:
        type: all
        of:
          # 1) в слот 13 вообще что-то положено
          - type: slot_filled
            slot: 13
          # 2) меч ещё не улучшен до потолка кузницы
          - type: not
            of:
              type: slot_matches
              slot: 13
              enchants:
                sharpness: 6
          # 3) у игрока есть плата
          - type: has_item
            material: GOLD_INGOT
            amount: 1
      deny:
        - type: message
          text: "&cНужен меч в центре, золотой слиток в инвентаре, и меч ещё не на максимуме."
        - type: sound
          sound: "minecraft:block.anvil.land"
    clicks:
      any:
        # Списание — гейт: не хватило слитка, и всё, что ниже, НЕ выполнится.
        - type: take_item
          material: GOLD_INGOT
          amount: 1
        - type: sound
          sound: "minecraft:block.anvil.use"

        # outcome — РОВНО ОДНА ветка. weight это не проценты: 60/35/5 == 12/7/1.
        - type: outcome
          outcomes:

            # ---- 60: успех -------------------------------------------------
            - weight: 60
              actions:
                # modify_slot правит ТОТ ЖЕ предмет: старые чары, прочность и
                # чужой NBT остаются, меняется только перечисленное здесь.
                - type: modify_slot
                  slot: 13
                  add-enchant:
                    sharpness: 6      # ограничение уровня игнорируется
                    unbreaking: 3
                  set-name: "&6Клинок кузницы"
                  add-lore:
                    - "&8Закалён в кузнице"
                  damage: -200        # минус чинит, плюс изнашивает
                - type: message
                  text: "&aКовка удалась! &7Клинок стал сильнее."
                - type: sound
                  sound: "minecraft:entity.player.levelup"
                - type: message
                  text: "&d* Идеальный удар! &7Кузнец доволен."
                  chance: 12.5        # дробные проценты работают

            # ---- 35: ничего ------------------------------------------------
            - weight: 35
              actions:
                - type: message
                  text: "&eСлиток сгорел впустую. &7Меч не пострадал."
                - type: sound
                  sound: "minecraft:block.fire.extinguish"

            # ---- 5: провал -------------------------------------------------
            - weight: 5
              actions:
                # clear_slot стирает содержимое слота — предмет исчезает ЗАКОННО,
                # это и есть цена риска. Мягче: modify_slot с damage: 300,
                # add-amount: -1 или add-enchant: { sharpness: 0 }.
                - type: clear_slot
                  slot: 13
                - type: message
                  text: "&c&lПРОВАЛ! &7Меч рассыпался в руках кузнеца."
                - type: sound
                  sound: "minecraft:entity.item.break"

  # --- INPUT-СЛОТ ---------------------------------------------------------
  '13':
    input:
      accept:
        - material: [DIAMOND_SWORD, NETHERITE_SWORD]
          min-amount: 1
      max-amount: 1
      lock-extract: false
      placeholder:
        material: GRAY_STAINED_GLASS_PANE
        name: "&7Положи сюда меч"
        lore:
          - "&8Алмазный или незеритовый"
      on-insert:
        - type: message
          text: "&7Меч лёг на наковальню."
        - type: sound
          sound: "minecraft:block.smithing_table.use"
      on-extract:
        - type: message
          text: "&7Меч снят с наковальни."
      on-reject:
        - type: message
          text: "&cКузнец берёт только алмазные и незеритовые мечи."
        - type: sound
          sound: "minecraft:block.anvil.land"

  # --- Забрать предмет ----------------------------------------------------
  '15':
    material: HOPPER
    name: "&eЗабрать меч"
    lore:
      - "&8Он и так вернётся сам при закрытии меню."
    click-requirement:
      require:
        type: slot_filled
        slot: 13
      deny:
        - type: message
          text: "&7В слоте и так пусто."
    clicks:
      any:
        - type: give_slot
          slot: 13

  '22':
    material: BARRIER
    name: "&cЗакрыть"
    clicks:
      any:
        - type: close
```

## Ключи `input:`

| Ключ | Тип | По умолчанию | Назначение |
|---|---|---|---|
| `accept` | список фильтров | пусто | Что слот **принимает**. Пусто/нет ключа = принимать что угодно. Список — это **ИЛИ**: достаточно совпасть с одним фильтром. |
| `max-amount` | число | `1` | Сколько предметов влезает в ячейку. Диапазон **1–64**; вне его обрезается с предупреждением в лог. |
| `lock-extract` | bool | `false` | `true` — положить можно, **забрать нельзя** (блокируется и обмен предметов через слот). Вещь всё равно вернётся при закрытии меню. |
| `placeholder` | секция | — | «Фон» пустой ячейки: только картинка. Игрок её не заберёт и в инвентарь она не попадёт. Нет секции — пустая ячейка. |
| `on-insert` | список действий | — | После **успешной** вставки предмета. |
| `on-extract` | список действий | — | После изъятия предмета из слота. |
| `on-reject` | список действий | — | Когда игрок пытается положить **неподходящий** предмет (вставка отменяется, предмет остаётся у него). |

### `placeholder`

Разбирается как обычный предмет, но **без** `clicks`, требований и голов игрока:

| Поле | По умолчанию | Назначение |
|---|---|---|
| `material` | `GRAY_STAINED_GLASS_PANE` | Материал фона. Неизвестный → `GRAY_STAINED_GLASS_PANE` + предупреждение в лог. |
| `name` | — | Имя (цвета как везде). |
| `lore` | — | Лор (список строк). |
| `cmd` | — | Строковый custom-model-data. |
| `flags` / `hide-all` | — | Скрыть item-flags, как у обычного предмета. |

!!! tip "У самого input-элемента `material:` не нужен"
    Input-слот не рисуется как обычный предмет — его картинка это `placeholder`. Заданный рядом
    `material:` просто не используется.

### Действия слота (`on-insert` / `on-extract` / `on-reject`)

Это обычные списки [действий](Actions.md) — `message`, `sound`, `run_command`, `give_item`, что угодно.
Выполняются **следующим тиком** после изменения слота (иначе шифт-клик успевал откатить правки инвентаря,
сделанные действием). Если за этот тик игрок закрыл меню или ушёл в другое — действия отменяются.

## Фильтры `accept:`

`accept:` — список фильтров, между ними **ИЛИ**. Внутри одного фильтра все заданные поля работают как **И**.

```yaml
input:
  accept:
    # Вариант 1: любой алмазный/незеритовый меч
    - material: [DIAMOND_SWORD, NETHERITE_SWORD]
    # ИЛИ вариант 2: именная реликвия любого материала
    - name-contains: "Древний"
      enchants:
        sharpness: 4
```

| Поле | Тип | Что проверяет |
|---|---|---|
| `material` | строка **или** список | Материал предмета. Список = любой из перечисленных. Неизвестный материал пропускается с предупреждением. |
| `name-equals` | строка | **Точное** совпадение имени. Регистр **важен**. |
| `name-contains` | строка | Имя содержит подстроку. Регистр **не важен**. |
| `lore-contains` | строка или список | Каждая строка должна найтись хотя бы в одной строке лора. Регистр **не важен**. |
| `cmd` | число | custom-model-data. Понимает и новый строковый компонент, и легаси-число. |
| `tag` | `namespace:key` | PDC-ключ другого плагина — проверяется только **наличие**, значение любое. Битый ключ пропускается с предупреждением. |
| `min-amount` | число | Минимальный размер стека (по умолчанию `1`). |
| `enchants` | карта | **Минимальные** уровни зачарований: `sharpness: 4` = «острота 4 и выше». Понимает и книги зачарования. |

### Как сравниваются имя и лор

Образец из конфига и имя предмета приводятся к **плоскому тексту без цвета**, и только потом сравниваются.
Поэтому `name-equals: "&6Клинок кузницы"`, `name-equals: "#ffaa00Клинок кузницы"` и
`name-equals: "<gradient:#ff5555:#ffaa00>Клинок кузницы"` ведут себя одинаково — пиши в той нотации, в
которой удобно. Цвет самого предмета на совпадение не влияет.

### Имена зачарований

Современные ключи реестра (`sharpness`, `unbreaking`, `fire_aspect`, можно с префиксом
`minecraft:`) и старые до-1.13 имена (`damage_all`, `dig_speed`, `durability`, `loot_bonus_blocks` и т.п.).
Неизвестное имя пропускается с предупреждением в лог — фильтр от этого не ломается, просто работает по
остальным полям.

!!! warning "Тот же словарь используют `take_item`, `has_item` и `slot_matches`"
    Все четыре места читают фильтр одинаково. Если гейт (`has_item`) и оплата (`take_item`) описаны
    **разными** полями — гейт пропустит того, с кого списать не получится.

## Как читать и править слот

| Что нужно | Инструмент | Страница |
|---|---|---|
| «в слоте пусто / что-то есть» | требования `slot_empty`, `slot_filled` | [Requirements](Requirements.md) |
| «в слоте лежит именно ЭТО» | требование `slot_matches` (те же поля, что у `accept`) | [Requirements](Requirements.md) |
| улучшить предмет игрока, сохранив чары/прочность/NBT | действие `modify_slot` | [Actions](Actions.md) |
| положить в слот новый предмет | действие `set_slot` | [Actions](Actions.md) |
| стереть содержимое слота | действие `clear_slot` | [Actions](Actions.md) |
| отдать содержимое игроку и опустошить слот | действие `give_slot` | [Actions](Actions.md) |
| взять плату из инвентаря игрока | действие `take_item` | [Actions](Actions.md) |
| выбрать один исход из нескольких | действие `outcome` | [Actions](Actions.md) |

Все слот-действия обязаны нести `slot: <номер>` — номер input-слота **того меню, которое сейчас открыто**.

## Сохранность предметов

Главный вопрос к такой фиче — «а не сожрёт ли оно мой меч». Не сожрёт. Содержимое слота — это вещь игрока,
и плагин отдаёт её обратно во всех сценариях:

| Что произошло | Куда уходит предмет |
|---|---|
| Игрок закрыл меню (`close`, Esc, `open_menu` в другое меню) | В инвентарь. Что не влезло — **падает под ноги**. |
| Игрок вышел с сервера | В инвентарь (он сохраняется уже после выхода). Что не влезло — в `pending/` до следующего входа. |
| Игрок умер | Вещь попадает в общий дроп вместе с остальным инвентарём. При `keepInventory` (или отменённой смерти) — возвращается в инвентарь, а не роняется на землю. |
| `/am reload` | Окна с непустыми слотами закрываются, вещи возвращаются владельцам **до** перезагрузки меню. |
| Выключение плагина (`/stop`, `/reload confirm`, PlugMan) | Синхронная выдача в инвентарь прямо на `onDisable`; выдать некому — в `pending/`. |
| **Краш / убитый процесс сервера** | Снимок слота лежит на диске в `plugins/AlexMenus/pending/`; при следующем входе игрока вещи выдаются, файл удаляется, в лог пишется строка о возврате. |

Как это устроено:

- После **каждой** правки слота сессия пишет снимок в `plugins/AlexMenus/pending/<uuid игрока>-<id
  сессии>.dat` (атомарная запись — обрезанного файла на диске не бывает).
- У каждого открытия меню — **своя** сессия со своим файлом, поэтому живое меню не может затереть снимок,
  оставшийся от краша, а вход не может выдать копию того, что прямо сейчас лежит в открытом слоте.
- Выдача **идемпотентна**: по одному закрытию окна обычно срабатывает несколько обработчиков (InvUI,
  выход, смерть, `onDisable`) — вещи забираются ровно один раз.
- Папку `pending/` руками трогать не надо. Она пуста, пока никто не держит предмет в слоте.

!!! note "Креатив"
    По умолчанию (`input-slots.deny-creative: true` в [config.yml](Configuration.md)) вещи из **креативного**
    режима в input-слот не кладутся: там стек бесконечный, и на выходе это был бы дюп. Отключается на свой
    страх и риск.

## Ограничения

Плагин проверяет их сам и пишет в лог при загрузке меню.

| Ограничение | Что происходит |
|---|---|
| **`input:` несовместим с `type: inventory`** | Элемент **выбрасывается** с громким предупреждением: бэкенд инвентарь-меню перерисовывает слоты 9–35 целиком и уничтожил бы положенную вещь. Input-слоты работают только в `type: chest`. |
| **`update-interval` + `input:`** | Интервал принудительно гасится в `0` (с предупреждением). Живой перерендер стёр бы содержимое слота вместе с предметом игрока. |
| **`view-requirement` на input-слоте** | Игнорируется (с предупреждением). Спрятать слот значило бы спрятать чужой предмет. |
| **`clicks:` и `click-requirement` на самом input-слоте** | Не выполняются: ячейка целиком отдана игроку, кликами по ней распоряжается инвентарь, а не меню. Логику вешают на **соседнюю кнопку** — в примере выше это молот в слоте `11`. |

Что при этом **можно**:

- несколько input-слотов в одном меню (заготовка + руна + катализатор). При шифт-клике они наполняются
  слева направо, сверху вниз;
- обычные предметы, кнопки, `view-requirement` и анимация открытия в том же меню — ограничения касаются
  только самих input-ячеек;
- `delay` у слот-действий: отложенное действие привязано к **той** сессии, из которой его поставили. Если
  игрок за это время закрыл меню или открыл другое, действие тихо отменяется (в `debug`-логе видно) — чужой
  предмет оно не тронет.

## Частые ошибки

- **Повесили `clicks:` на сам input-слот** — ничего не происходит. Нужна отдельная кнопка рядом.
- **Забыли `slot:` у `modify_slot`/`clear_slot`/`set_slot`/`give_slot`** — действие пропускается с
  предупреждением в лог.
- **Указали в `slot:` номер обычного предмета, а не input-слота** — `slot_empty` пройдёт, а
  `slot_filled`/`slot_matches` провалятся; в лог один раз напишется, что такого input-слота в меню нет.
- **Гейт по `has_item` описан не теми полями, что `take_item`** — гейт пропускает, оплата промахивается,
  цепочка обрывается на списании (см. [Actions](Actions.md)).
- **`take_item` без единого поля фильтра** — пустой фильтр совпал бы с любым предметом инвентаря, поэтому
  действие **пропускается вместе со всем, что после него**.
