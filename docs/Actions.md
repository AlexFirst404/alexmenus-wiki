# Действия (actions)

Действие — YAML-карта с полем `type` и параметрами. Действия задаются списком: в `clicks.<тип>`, в
`deny`/`success` требований (см. [Requirements](Requirements.md)) и в ветках `then`/`else` действия
`conditional`. Выполняются по порядку.

```yaml
clicks:
  left:
    - type: message
      text: "<green>Привет!"
    - type: sound
      sound: "minecraft:ui.button.click"
```

## Модификаторы на ЛЮБОМ действии

| Модификатор | Значение | Поведение |
|---|---|---|
| `chance` | `0–100`, **дробные разрешены** | Шанс выполнения в процентах. `100`/нет = всегда; `0` = никогда; `12.5` = 12.5 %. Применяется, только если ключ `chance` присутствует. |
| `delay` | тики | Отложить действие на N тиков (20 тиков = 1 сек). Через `delay` тиков проверяется, что игрок ещё онлайн. `0`/нет = сразу. |

```yaml
- type: give_item
  material: DIAMOND
  chance: 25        # выпадет примерно в 25% кликов
- type: message
  text: "<gray>Редкая реплика"
  chance: 12.5      # дробные проценты работают
- type: message
  text: "<gray>...сообщение через секунду"
  delay: 20         # покажется через 20 тиков
```

!!! info "Дробный `chance` теперь считается по-настоящему"
    Раньше значение читалось целым числом, и `chance: 12.5` молча округлялось в ноль — то есть действие
    срабатывало **всегда**. Теперь это честные 12.5 %.

Битое значение (`chance:` без числа, `chance: часто`) — **fail-open**: действие выполняется каждый раз, но
плагин один раз ругается в лог. Опечатка не должна тихо ломать выдачу на живом сервере, но и незамеченной
остаться не должна.

## Оплата обрывает цепочку

Действия-списания — `take_item`, `take_money`, `take_exp` — работают как **гейт**, а не как пожелание.
Если списать не удалось (не хватило, нет Vault, битый `amount:`), **всё, что стоит после них в списке, не
выполняется**.

```yaml
clicks:
  any:
    - type: take_money
      amount: 100
    - type: give_item      # не выдастся, если денег не хватило
      material: DIAMOND
    - type: message        # и это тоже не покажется
      text: "&aКуплено!"
```

Ровно то же правило действует внутри `conditional` (`then`/`else`) и `outcome`: провалившееся списание во
вложенной ветке обрывает и внешний список — гейт нельзя обойти вложением.

!!! warning "`delay` у списания — это дыра"
    Отложенное списание физически не может остановить то, что выполнилось раньше него. Плагин ругается в
    лог, если у `take_*` стоит `delay:`. Либо убери задержку, либо положи награду в ту же отложенную ветку.

## Справочник действий

### `run_command`

Выполнить команду. `command` — сам текст (лидирующий `/` можно опустить). `as: player|console` (по
умолчанию `player`). Текст разворачивает плейсхолдеры (`%...%`).

```yaml
- type: run_command
  as: console
  command: "give %player_name% diamond 1"
- type: run_command
  as: player            # по умолчанию — от имени игрока
  command: "spawn"
```

### `message`

Отправить сообщение игроку. Поле `text` (цвета + плейсхолдеры).

```yaml
- type: message
  text: "<green>Ты нажал кнопку, %player_name%!"
```

### `broadcast`

Сообщение **всему серверу**. Поле `text`.

```yaml
- type: broadcast
  text: "<gold>%player_name% <yellow>купил награду!"
```

### `title`

Показать **титул** (большой текст по центру) + подзаголовок с таймингами появления/показа/исчезновения.
Тайминги — в **тиках** (20 тиков = 1 сек). Все поля опциональны.

| Поле | По умолчанию | Назначение |
|---|---|---|
| `title` | `""` | Основной текст (цвета/плейсхолдеры/`{аргументы}`). |
| `subtitle` | `""` | Подзаголовок. |
| `fade-in` | `10` | Тики появления. |
| `stay` | `40` | Тики показа. |
| `fade-out` | `10` | Тики исчезновения. |

```yaml
- type: title
  title: "<gradient:#ffd700:#ff8800>Добро пожаловать!"
  subtitle: "<gray>%player_name%"
  fade-in: 10
  stay: 60
  fade-out: 20
```

### `actionbar`

Сообщение в **action bar** (узкая строка над хотбаром). Поле `text` (цвета/плейсхолдеры/`{аргументы}`).

```yaml
- type: actionbar
  text: "<green>Баланс: <white>%vault_eco_balance%"
```

### `open_menu`

Открыть другое меню (переход, кладётся в историю навигации). Поле `menu` — id меню.

```yaml
- type: open_menu
  menu: shop
```

### `back`

Вернуться к предыдущему меню в истории. Если истории нет — закрывает окно.

```yaml
- type: back
```

### `refresh`

Перерисовать текущее меню на месте (пере-вычисляет плейсхолдеры/видимость).

```yaml
- type: refresh
```

### `close`

Закрыть меню и очистить историю навигации.

```yaml
- type: close
```

### `sound`

Проиграть звук игроку. Поле `sound` — ключ звука (`namespace:path`). Громкость/высота фиксированы (1.0),
источник `MASTER`. Битый ключ звука логируется, но не крашит.

```yaml
- type: sound
  sound: "minecraft:entity.experience_orb.pickup"
```

> Дополнительных полей громкости/высоты нет — читается только `sound`.

### `connect` (алиас `server`) — прокси Bungee/Velocity

Отправить игрока на **другой сервер** сети через плагин-канал `BungeeCord` (его понимают и BungeeCord, и
Velocity). Поле `server` — имя сервера в конфиге прокси. Разворачивает плейсхолдеры/`{аргументы}`. Пустое имя
— no-op.

```yaml
- type: connect
  server: lobby
# алиас `server` — то же самое:
- type: server
  server: survival
```

> Требуется прокси (BungeeCord/Velocity/Waterfall) с настроенными серверами; на одиночном сервере действие
> ничего не делает. Имя сервера — как в конфиге прокси, не адрес.

### `give_item`

Выдать предмет в инвентарь. Поля как у предмета меню + `amount` и `menu`.

| Поле | Назначение |
|---|---|
| `material` | Материал (не-предмет/неизвестный → `STONE`). |
| `cmd` | Строковый custom-model-data. |
| `name` | Имя. |
| `lore` | Лор (список). |
| `flags` / `hide-all` | Скрыть item-flags (`hide-all: true` — все). |
| `amount` | Количество (минимум 1). Больше стака — режется на нормальные стаки; абсурдные значения обрезаются с предупреждением. |
| `menu` | Если задано — на предмет вешается PDC-тег меню: **ПКМ этим предметом открывает меню** `menu`. |

> Что не влезло в инвентарь — **падает под ноги** игроку, а не пропадает.

```yaml
# обычная выдача
- type: give_item
  material: GOLDEN_APPLE
  amount: 2
# «предмет-открывашка» меню (ПКМ → открыть меню main)
- type: give_item
  material: NETHER_STAR
  name: "<gold>Меню сервера"
  hide-all: true
  menu: main
```

### `give_money` / `take_money` — нужен Vault

Выдать/снять деньги. Поле `amount` (парсится в число, минимум 0).

- `give_money` — награда: не удалось выплатить (нет Vault/экономики) → предупреждение в лог, цепочка идёт
  дальше.
- `take_money` — **оплата**: не удалось списать → срабатывает звук `sounds.deny` и **вся оставшаяся цепочка
  отменяется**. Это касается и случая, когда Vault **не установлен**: раньше товар при этом выдавался
  бесплатно, теперь — не выдаётся вообще.
- Не-число в `amount` у `take_money` — тоже отказ (молчаливый ноль означал бы «бесплатно»).
- `take_money` c `amount: 0` — законный no-op, цепочку не трогает.

```yaml
- type: take_money
  amount: 100
- type: give_money
  amount: 50
```

### `give_exp` / `take_exp`

Выдать/снять опыт. Поля `amount` (минимум 0) и `level: true|false`.

- `level: true` — работает с **уровнями**.
- `level: false`/нет — работает с **очками** опыта (считается истинный суммарный опыт, а не ванильный
  счётчик — тот же источник, что у требования `exp`).
- `take_exp` — **оплата** по принципу «всё или ничего»: не хватило — не снято ничего и цепочка обрывается
  (раньше уровень просто прижимался к нулю, а награда всё равно выдавалась).

```yaml
- type: give_exp
  amount: 5
  level: true          # +5 уровней
- type: take_exp
  amount: 100          # −100 очков опыта
```

### `take_item` — плата предметом

Списать предметы из инвентаря игрока. Поле `amount` — сколько взять (по умолчанию `1`), остальные поля —
**фильтр предмета** (тот же словарь, что у `input.accept` и требования `has_item`, см.
[Input-Slots](Input-Slots.md)).

| Поле | Назначение |
|---|---|
| `amount` | Сколько предметов списать (минимум 1). |
| `material` | Материал: строка или список. |
| `name-equals` / `name-contains` | Имя целиком (регистр важен) / подстрока имени (регистр не важен). |
| `lore-contains` | Строка или список подстрок лора. |
| `cmd` | custom-model-data. |
| `tag` | PDC-ключ `namespace:key` (проверяется наличие). |
| `min-amount` | Минимальный размер стека, который вообще считается подходящим. |
| `enchants` | Минимальные уровни зачарований. |

```yaml
# обычный слиток
- type: take_item
  material: GOLD_INGOT
  amount: 1

# именной «Кузнечный слиток» — обычным за него не заплатишь
- type: take_item
  material: GOLD_INGOT
  name-contains: "Кузнечный"
  amount: 1
```

Правила:

- **Всё или ничего**: не хватило — не снято ничего, цепочка обрывается (наполовину оплаченной покупки не
  бывает).
- Смотрит **только 36 основных слотов** (хотбар + основной инвентарь). Броня и офф-хенд не трогаются
  никогда — списывать плату из надетой брони значило бы молча раздевать игрока.
- **Фильтр без единого поля** (`- type: take_item` и всё) — действие пропускается **вместе со всем, что
  после него**: пустой фильтр совпал бы с каждым предметом инвентаря.

### `outcome` — ровно один исход из нескольких

Выбрать и выполнить **ровно одну** ветку из `outcomes:` по весу `weight`.

```yaml
- type: outcome
  outcomes:
    - weight: 60
      actions:
        - type: message
          text: "&aУспех!"
    - weight: 35
      actions:
        - type: message
          text: "&eНичего не вышло."
    - weight: 5
      actions:
        - type: message
          text: "&cПровал!"
```

| Поле | Назначение |
|---|---|
| `outcomes` | Список веток. Каждая ветка — карта с `weight:` и `actions:`. |
| `weight` | Вес ветки. Нет ключа = `1`. Отрицательный/нечисловой = `0` (в лог пишется предупреждение). |
| `actions` | Список действий ветки — любые действия, включая вложенные `outcome`/`conditional`. |

!!! important "Веса — это НЕ проценты"
    Веса нормируются собственной суммой, поэтому `60/35/5` и `12/7/1` ведут себя **одинаково**. Благодаря
    этому добавление новой ветки не требует пересчитывать остальные.

Ветка выполняется так же, как `then`/`else` у `conditional`: её действия получают свои `chance`/`delay`, а
провалившееся внутри неё списание обрывает и внешнюю цепочку. Если `outcomes:` пуст или все веса нулевые —
не выполняется ничего (с предупреждением в лог).

### Действия по input-слотам

Работают со слотами, куда игрок кладёт свои вещи (`input:`, см. [Input-Slots](Input-Slots.md)). У всех
обязателен `slot:` — номер input-слота **открытого сейчас** меню; без него действие пропускается с
предупреждением.

#### `modify_slot` — править предмет игрока на месте

Основное действие для прокачки: меняет **тот же** предмет, поэтому старые зачарования, прочность и чужой
NBT сохраняются — трогаются только перечисленные ключи.

| Поле | Назначение |
|---|---|
| `slot` | Номер input-слота (обязателен). |
| `set-material` | Сменить материал, перенеся на него существующую мету (железный меч → алмазный с теми же чарами). |
| `set-name` | Новое имя. **Пустая строка** снимает кастомное имя и возвращает ванильное. |
| `set-lore` | Заменить лор целиком (строка или список). |
| `add-lore` | Дописать строки в конец лора. |
| `add-enchant` | Карта `зачарование: уровень`. Ограничения уровня **игнорируются** (кузница на то и кузница). Уровень `0` или меньше — снять зачарование. |
| `remove-enchant` | Имя или список имён зачарований на снятие. |
| `set-amount` | Установить количество. |
| `add-amount` | Прибавить к количеству (отрицательное — убавить). Ноль и меньше — **слот пустеет**. |
| `set-cmd` | Строковый custom-model-data. Пусто — очистить (в том числе легаси-число). |
| `damage` | **Плюс изнашивает, минус чинит.** Обрезается по прочности предмета. У предметов без прочности игнорируется. |

```yaml
- type: modify_slot
  slot: 13
  add-enchant:
    sharpness: 6
    unbreaking: 3
  set-name: "&6Клинок кузницы"
  add-lore:
    - "&8Закалён в кузнице"
  damage: -200          # починить на 200 единиц прочности
```

#### `set_slot` — положить в слот новый предмет

Полностью заменяет содержимое слота свежесобранным предметом. Поля как у `give_item`: `material`
(обязателен), `name`, `lore`, `cmd`, `amount`, `flags`/`hide-all`.

```yaml
- type: set_slot
  slot: 13
  material: NETHERITE_INGOT
  name: "&fСплав кузницы"
  amount: 1
```

#### `clear_slot` — стереть содержимое

```yaml
- type: clear_slot
  slot: 13
```

Предмет исчезает **законно** — это цена риска, а не потеря. Мягкие альтернативы провала: `modify_slot` с
`damage: 300` (износ), `add-amount: -1` (убавить) или `add-enchant: { sharpness: 0 }` (снять чары).

#### `give_slot` — отдать содержимое игроку

Кладёт содержимое слота в инвентарь и опустошает слот. Что не влезло — падает под ноги.

```yaml
- type: give_slot
  slot: 13
```

### `give_permission` / `take_permission` — нужен Vault или LuckPerms

Выдать/снять пермишен-нод игроку. Поле `permission` — сам нод (разворачивает плейсхолдеры/`{аргументы}`).
Мутация идёт через мягкий пермишен-хук (**Vault** с провайдером прав или **LuckPerms** напрямую).

```yaml
- type: give_permission
  permission: alexmenus.menu.vip
- type: take_permission
  permission: essentials.fly
```

> Если ни Vault-провайдера прав, ни LuckPerms нет — действие пропускается с предупреждением в лог (нод не
> меняется, краша нет). Пустой `permission` — no-op. Изменения применяются к онлайн-игроку, который кликнул.

### `conditional`

Ветвление по условию. Поле `requirement` (см. [Requirements](Requirements.md)) → выполнить `then` при успехе,
иначе `else`. Обе ветки — списки действий.

```yaml
- type: conditional
  requirement:
    type: permission
    permission: alexmenus.vip
  then:
    - type: message
      text: "<aqua>Ты VIP!"
  else:
    - type: message
      text: "<gray>Обычный игрок."
    - type: open_menu
      menu: buy_vip
```

## Разворачивание текста

В текстовых полях действий (`command`, `text`, `title`/`subtitle`, `server`, `permission`, а также
`name`/`lore` у `set_slot` и `set-name`/`set-lore`/`add-lore` у `modify_slot`) сначала
подставляются `{ключ}` — [аргументы меню](Advanced-Menu-Options.md) (`args`: `{имя}`, `{argN}`, `{args}`), затем
разворачиваются плейсхолдеры PlaceholderAPI (`%...%`), если он установлен. Если у меню нет `args` и токенов не
передавали — подстановка `{...}` просто ничего не меняет. Подробнее —
[Placeholders-and-Integrations](Placeholders-and-Integrations.md).

> Неизвестный `type` действия просто логируется предупреждением и пропускается.
