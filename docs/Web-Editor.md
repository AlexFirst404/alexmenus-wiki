# Веб-редактор

Веб-редактор AlexMenus сделан **в стиле LuckPerms**: на игровом сервере **не открывается ни один порт**.
Плагин делает только **исходящие HTTPS-запросы** к маленькому paste-сервису (Cloudflare Worker), а правишь
меню в **хостед**-редакторе (статическая страница на GitHub Pages).

## Как это работает

```
/am editor
   → плагин собирает YAML всех меню в бандл
   → POST на paste-сервис  → получает короткий код
   → печатает ссылку  <editor-url>#<код>   (кликабельна в чате)

(открываешь ссылку, правишь меню мышкой в браузере, «Сохранить» → редактор выдаёт код)

/am apply <код>
   → GET бандла с paste-сервиса по коду
   → пишет каждый menus/<id>.yml
   → перезагружает плагин
```

Детали (`bridge/EditorBridge.java`, `command/AlexMenusCommand.java`):

- **Бандл**: JSON `{"v":1,"menus":[{"id":..,"yaml":..}, …]}` — сырой YAML каждого меню.
- **Ссылка** — чистая `<editor>#<код>`. Адрес воркера в ссылку **не попадает** (он вшит в хостед-редактор),
  так что о paste-хосте ничего не утекает.
- Сетевые операции (`push`/`fetch`) идут **асинхронно** (не вешают основной поток); запись файлов и reload —
  в основном потоке.
- `apply` пишет в существующий файл меню, если id уже известен; для **нового** id — в `menus/<id>.yml`
  (в корень категории `general`). Id санитизируется: остаются только `a-z 0-9 _ -`.
- Код (paste) живёт ограниченное время — **24 часа** (по умолчанию у публичного воркера); истёкший код на
  `/am apply` даёт «код не найден или истёк».

## Возможности редактора

- **Мультивыделение слотов** и **контекстное меню** (ПКМ) для быстрых операций.
- **Иконки как в игре** — модель-осознанные превью, блоки рисуются 3D-кубом.
- **Панели requirements** — `view` / `click` / `open` без ручного YAML; композиты (`all`/`any`/`not`) — через
  режим «Расширенно».
- **Вид «Граф»** — кто из какого меню куда ведёт (по действиям `open_menu`).
- **Панель «Настройки меню»** — тип, заголовок, ряды, команды, права, open-requirement.
- **Сырой YAML** — режим прямого редактирования текста меню.
- **[Анимации](Animations.md)** — редактор кадров предмета (`animation:`: интервал, режим повтора, список
  кадров) с **живым превью прямо в ячейке сетки** и клик-сетка для сбора ручного порядка `order:` у
  `open-animation`. Ползунок темпа размечен на всю шкалу **1–200 %** и показывает, сколько шагов уйдёт в
  один тик.

### Интерфейс (обновлён в 1.8.0)

- **Перетаскиваемые границы колонок** — ширину панелей можно тянуть мышью.
- **Сворачиваемые секции (аккордеоны)** — длинные панели свойств складываются.
- **Стрелки-степперы** у всех числовых полей + **прокрутка колесом** в настройках меню.
- **`hide-all` перенесён наверх** секции флагов — самый частый переключатель теперь первый.
- Единая шкала отступов по всему интерфейсу.

!!! info "Редактор знает те же алиасы, что и плагин"
    Таблица алиасов `loop` (включая `ping_pong` и строку `'false'`) в редакторе повторяет
    `ItemAnimation.Loop` один-в-один. До 1.9.0 её там не хватало, и сохранение меню **переписывало** такие
    режимы (например `loop: ping_pong` превращался в `loop: true`). Если ты правил анимации руками и потом
    сохранял через редактор — сверь режимы повтора.

## Настройка: её нет

Редактор **не настраивается** — и настраивать нечего. Адрес хостед-редактора и адрес paste-воркера **зашиты
в плагин**, поэтому `/am editor` работает сразу после установки, на любом сервере, без единой строчки в
конфиге.

!!! danger "Блок `editor:` удалён в 1.7.0"
    Раньше в `config.yml` была секция `editor:` с ключами `worker-url` и `url`. **Её больше нет.** Если она
    осталась в старом конфиге, плагин **напишет предупреждение в лог и проигнорирует её** — ничего не
    сломается, но и подменить адреса через неё уже нельзя. Секцию можно удалить.

    Вместе с этим **отпал и self-host paste-воркера**: подставить свой адрес плагину больше некуда.

Текущий адрес редактора всегда видно в **`/am info`** (см.
[Commands-and-Permissions](Commands-and-Permissions.md)).

## Что уходит наружу

- Только **исходящие HTTPS**-запросы: `POST` бандла меню при `/am editor` и `GET` бандла при `/am apply`.
- На сервере **не открывается ни один порт**, фоновых потоков редактор не держит.
- В ссылку попадает только код бандла — адрес paste-хоста в ней не светится.
- Бандл — это YAML твоих меню. Ничего другого (инвентари игроков, права, конфиг) плагин никуда не
  отправляет.
