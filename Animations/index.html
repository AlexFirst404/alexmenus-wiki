    Анимации¶

    В AlexMenus две независимые анимации, и путать их не стоит:

    Что Где задаётся Что делает
    Анимация открытия open-animation: — ключ меню Предметы появляются по очереди при открытии. Разовый эффект.
    Анимированные предметы animation: — ключ предмета (items.<slot>.animation) Предмет перебирает кадры, пока меню открыто. Бесконечно (или до последнего кадра).

    Их можно включить одновременно: сначала меню «раскрывается», потом кадры продолжают крутиться.

    Обе анимации работают только на type: chest (см. Menu-Types). У inventory-меню нет объектов-предметов, которые можно перерисовать поштучно — там анимации нет, и animation: на элементе такого меню пишет предупреждение в лог и выбрасывается.

    Анимированные предметы (animation:)¶

    Ключ animation: у элемента превращает его в «кадровую» анимацию: раз в interval тиков предмет перерисовывается следующим кадром.

    type: chest
title: "&8Портал"
rows: 3
items:
  '13':
    material: LIME_CONCRETE          # БАЗОВЫЙ предмет
    name: "&aПортал"
    lore:
      - "&7Нажми, чтобы телепортироваться"
    animation:
      interval: 5                    # тиков на кадр (по умолчанию 10)
      loop: true                     # loop | once | pingpong (по умолчанию loop)
      frames:
        - {}                         # кадр 1 — базовый предмет как есть
        - material: GREEN_CONCRETE   # кадр 2 — меняется только материал
        - material: CYAN_CONCRETE
        - material: LIGHT_BLUE_CONCRETE
    clicks:
      any:
        - type: run_command
          command: "spawn"

    Поля блока animation:¶

    Поле По умолчанию Назначение
    interval 10 Тиков на один кадр (20 тиков = 1 сек). Минимум 1.
    loop loop Что делать после последнего кадра (см. таблицу ниже).
    frames — Список карт — кадры по порядку. Нужно минимум 2, иначе анимация выбрасывается с предупреждением.

    Значения loop¶

    loop: принимает и YAML-булево, и слово:

    Режим Что записать Поведение
    Зацикленно true, loop, или любое неизвестное значение 1 → 2 → 3 → 1 → 2 → 3 → …
    Один раз false, no, once, stop, hold Дойти до последнего кадра и остаться на нём.
    Туда-обратно pingpong, ping-pong, ping_pong, bounce, yoyo, alternate 1 → 2 → 3 → 2 → 1 → 2 → … крайние кадры не дублируются.

    loop: false — это YAML-булево, а не строка

    И loop: false, и loop: 'false' дают режим «один раз» — плагин понимает оба. Но в редакторе и в примерах используется именно булево false.

    Кадр наследует базовый предмет¶

    Кадр — это не целый предмет, а набор переопределений поверх базового. Всё, что кадр не упомянул, берётся из самого элемента (ItemSpec.merge). Поэтому:

    • - {} — пустой кадр — это ровно базовый предмет. Удобно как «нейтральный» кадр в начале.
    • Кадр, где написан только name:, меняет только имя: материал, лор, флаги, cmd остаются базовыми.
    items:
  '13':
    material: CLOCK
    name: "&eЗагрузка"
    lore:
      - "&7Подождите…"
    hide-all: true
    animation:
      interval: 4
      frames:
        - name: "&eЗагрузка &7|"     # лор, материал и hide-all унаследованы
        - name: "&eЗагрузка &7/"
        - name: "&eЗагрузка &7-"
        - name: "&eЗагрузка &7\\"

    Какие поля кадр может переопределить (те же, что у предмета, см. Items-and-Clicks):

    Поле кадра Поведение
    material Материал кадра. Неизвестный/не-предмет → предупреждение в лог, кадр наследует базовый материал. Понимаются DeluxeMenus-префиксы basehead-/texture-/head-.
    name Имя кадра. Пустая строка — это тоже переопределение (имя станет пустым), а не «унаследовать».
    lore Лор кадра: строка или список. lore: [] очищает лор, а отсутствие ключа — наследует.
    cmd Строковый custom-model-data кадра. Пустая строка = не задано → наследуется (очистить cmd в кадре нельзя).
    flags Список ItemFlag кадра (заменяет базовый список целиком).
    hide-all hide-all: true в кадре = все флаги.
    head-owner / head-uuid / head-texture Источник головы (см. ниже).

    Головы: три поля — одна группа

    Если кадр указал любой из head-owner / head-uuid / head-texture, он заменяет все три сразу. Иначе базовый head-texture пережил бы head-owner кадра и молча победил бы (текстура разбирается первой) — кадр выглядел бы проигнорированным.

    items:
  '11':
    material: PLAYER_HEAD
    head-texture: "eyJ0ZXh0dXJlcyI6ey..."   # база — кастомный скин
    name: "&6Голова"
    animation:
      interval: 20
      frames:
        - {}                                 # кадр 1 — базовая текстура
        - head-owner: "%player_name%"        # кадр 2 — голова смотрящего, текстура НЕ мешает

    Кадры и плейсхолдеры¶

    Кадр может содержать %плейсхолдеры% и {аргументы} меню — они разворачиваются на каждой перерисовке. Плагин определяет это при загрузке: кадр без плейсхолдеров собирается один раз и кэшируется, кадр с плейсхолдером пересобирается каждый раз (иначе живое значение застыло бы на первом прочитанном).

    items:
  '15':
    material: GOLD_INGOT
    animation:
      interval: 10
      frames:
        - name: "&eБаланс: &f%vault_eco_balance%"    # пересобирается каждый кадр
        - name: "&6Баланс: &f%vault_eco_balance%"

    Когда все видят один и тот же кадр¶

    Кадры считаются от одного общего счётчика тиков плагина, а не от момента открытия окна. Следствия (сделано намеренно):

    • два игрока, открывшие одно меню в разное время, видят один и тот же кадр в один и тот же момент — анимация принадлежит серверу, а не окну;
    • окно, открытое посреди цикла, начинается с середины цикла. Для крутящейся/пульсирующей декорации это как раз то, что нужно.

    Исключение — loop: false: «остановиться на последнем кадре» бессмысленно относительно счётчика, который идёт с запуска сервера (любое окно открывалось бы уже «доигравшим»). Такая анимация отсчитывается от момента открытия окна и всегда стартует с первого кадра.

    Ограничения и цена¶

    Правило Почему
    animation: нельзя на input-слоте Там лежит предмет игрока, а не наш Item. Перерисовка отвязала бы инвентарь от окна и визуально съела бы вещь. Плагин пишет предупреждение и выбрасывает анимацию.
    animation: не работает на type: inventory В инвентарном бэкенде нет объектов-предметов InvUI. Предупреждение в лог, ключ игнорируется.
    Нужно минимум 2 кадра Один кадр — это просто статичный предмет. Предупреждение в лог, анимация выбрасывается.
    Анимации не требуют update-interval Кадры крутит тот же общий тикер плагина. Это важно для меню с input-слотами: там update-interval принудительно 0, но анимации всё равно работают.

    Про производительность: в тике перерисовываются только те предметы, у которых кадр реально сменился, а меню без анимаций в живой список вообще не попадает и не стоит ничего.

    Анимация + view-requirement

    Анимированный предмет, скрытый view-requirement, всё равно занимает слот (как воздух) и может появиться позже, когда условие станет истинным — тикер перечитывает его сам. Обычный (не анимированный) предмет в статичном меню так не умеет: там нужен update-interval.

    Анимация открытия (open-animation)¶

    Секция верхнего уровня меню. Предметы расставляются не сразу, а пошагово, в геометрическом порядке.

    type: chest
title: "&6Магазин"
rows: 3
open-animation:
  type: spiral                        # порядок появления
  speed: 140                          # темп 1..200
  sound: "minecraft:ui.button.click"  # звук на каждый тик, опц.
items:
  '0': { material: DIAMOND, name: "&b1" }
  '4': { material: EMERALD, name: "&a2" }
  '8': { material: GOLD_INGOT, name: "&e3" }
    Поле По умолчанию Назначение
    type none Порядок появления (таблица ниже). Неизвестное значение → none (анимации нет).
    speed — Темп 1..200. Задан — управляет темпом целиком (см. ниже).
    interval 2 Легаси: тики между шагами напрямую. Читается только если speed не задан; всегда один шаг за тик.
    sound — Ключ звука (namespace:path) — играет раз в тик. Битый ключ логируется, меню не ломается.
    order — Явный список слотов для type: custom (см. ниже).

    speed: — темп до 200 %¶

    До 100 % темп задаётся интервалом между шагами. 100 % — это один шаг за тик, физический потолок повторяющейся задачи Bukkit. Выше 100 % интервал уменьшать уже некуда, поэтому за один тик выкладывается несколько шагов сразу (batch).

    speed Интервал Шагов за тик
    1 20 тиков 1
    25 16 тиков 1
    50 11 тиков 1
    75 6 тиков 1
    100 1 тик 1
    101–125 1 тик 2
    126–150 1 тик 3
    151–175 1 тик 4
    176–200 1 тик 5

    Тонкости:

    • Значения до 100 включительно ведут себя точно как раньше — старые меню темп не поменяли.
    • Значения вне 1..200 зажимаются в диапазон, а не отбрасываются.
    • Звук играет раз в тик, а не раз в шаг. Иначе на speed: 200 каждый тик накладывал бы пять копий одного звука друг на друга.
    • Если ключа speed: нет вообще — работает легаси-interval: (по умолчанию 2 тика на шаг, один шаг).
    • Пиши число без кавычек: speed: 150. Строку (speed: "150") или мусор Bukkit числом не считает и подставляет 50. То же правило у interval: — и у меню, и у предмета.

    Значения type¶

    Порядок появления — чистая геометрия сетки ряды × 9, поэтому все узоры одинаково корректны и на 1 ряду, и на 6.

    type Алиасы Порядок появления
    none — Без анимации — все предметы сразу (как без секции).
    sweep slots, slot По возрастанию слота, по одному слоту за шаг.
    rows row Ряд за рядом сверху вниз, целый ряд за шаг.
    columns column, cols, col Колонка за колонкой слева направо, целая колонка за шаг.
    random shuffle В перемешанном порядке, по одному слоту за шаг.
    corners corner Растёт внутрь сразу из четырёх углов.
    edges converge, top_bottom, top-bottom Верхний и нижний ряды первыми, сходятся к середине.
    ellipse oval, ripple, center Эллиптические кольца из трёх центральных слотов до всех краёв.
    spiral — Спираль по часовой стрелке от внешней рамки внутрь, по одному слоту за шаг.
    center-out center_out, centerout, outward, explode Квадратные кольца от геометрического центра к краям («взрыв»).
    diagonal diag Диагональные волны от левого верхнего угла, целая диагональ за шаг.
    snake zigzag, boustrophedon Змейка: ряд 0 слева направо, ряд 1 справа налево, и так далее.
    custom order, manual Порядок, выписанный вручную в order: (см. ниже).

    center — это ellipse, а не center-out

    Алиас center означает эллиптические кольца ещё с момента появления фичи, и это специально не меняли, чтобы существующие меню не поменяли форму молча. Для «взрыва из центра» пиши center-out.

    type: custom + order: — порядок вручную¶

    type: chest
rows: 3
open-animation:
  type: custom
  speed: 80
  order: [13, 4, 22, 12, 14, 3, 5, 21, 23]   # сначала центр, потом крест, потом углы
items:
  '13': { material: NETHER_STAR, name: "&bЦентр" }
  '4':  { material: DIAMOND, name: "&b2" }
  '22': { material: EMERALD, name: "&a3" }

    Правила order::

    • order: без type: — это очевидное намерение, type: custom подставляется сам. Писать оба ключа не обязательно.
    • Слоты, которые ты не перечислил, появляются одним последним шагом (по возрастанию). Забытый слот «покажется последним», а не «не покажется никогда».
    • Каждая проблема записи — предупреждение в лог, а не отказ загрузки: не-число, слот вне сетки 0..ряды*9-1 и повтор просто выбрасываются (у повтора выигрывает первое вхождение), остальной список работает.
    • type: custom с пустым/отсутствующим order: → берётся sweep (с предупреждением).
    • order: рядом с любым встроенным узором (type: spiral и т. п.) игнорируется с предупреждением: узор задаёт порядок сам.

    Исправлено в 1.9.0: type: none больше не «включается» из-за order:

    Раньше проверка смотрела на разобранное значение type, а оно сводит к none и отсутствующий ключ, и явный type: none, и опечатку. Из-за этого админ, выключивший анимацию через type: none поверх оставшегося длинного order:, молча получал её обратно как custom.

    Теперь смотрится наличие ключа: явный type: none выключает анимацию, а order: рядом с ним игнорируется с предупреждением в лог. То же и с опечаткой в типе (type: spirral) — она тоже сводится к none и тоже больше не «оживляет» оставшийся order:.

    Если ты держал order: как «черновик на будущее» и выключал анимацию через type: none — после обновления анимации в этом меню не будет (это и есть исправленное поведение). Чтобы вернуть — поставь type: custom.

    Что не участвует в анимации открытия¶

    • Скрытые предметы (view-requirement не выполнен) шагов не занимают: пустая ячейка, «раскрытая» со звуком, выглядела бы сломанной.
    • Пустые слоты тоже: шаг, в котором нет ни одного предмета, просто выбрасывается и тик не тратит.
    • Input-слоты привязываются отдельным проходом до анимации и никогда ей не перезаписываются (иначе вещь игрока была бы затёрта).
    • Если игрок закрыл окно посреди анимации — задача останавливается сама.

    Всё вместе¶

    type: chest
title: "&8» &6Кузница"
rows: 3
commands: [forge]

# меню «раскрывается» спиралью, быстро
open-animation:
  type: spiral
  speed: 160
  sound: "minecraft:block.note_block.hat"

items:
  # кадровая анимация: мигающая кнопка
  '11':
    material: LIME_CONCRETE
    name: "&aКовать"
    hide-all: true
    animation:
      interval: 6
      loop: pingpong
      frames:
        - {}
        - material: GREEN_CONCRETE
        - material: LIME_STAINED_GLASS
    clicks:
      any:
        - type: message
          text: "&aГотово!"

  # «загрузка» с остановкой на последнем кадре
  '15':
    material: HOPPER
    name: "&7Прогресс"
    animation:
      interval: 8
      loop: false
      frames:
        - name: "&7Прогресс &8[&f▌&8    ]"
        - name: "&7Прогресс &8[&f▌▌&8   ]"
        - name: "&7Прогресс &8[&f▌▌▌&8  ]"
        - name: "&aГотово &8[&a▌▌▌▌▌&8]"
