    Типы меню¶

    Тип задаётся ключом type на верхнем уровне YAML. Значения: chest (по умолчанию) и inventory.

    type: chest        # или inventory; любое другое/пустое значение = chest

    Настройки верхнего уровня (общие)¶

    Ключ Назначение
    type chest или inventory. По умолчанию chest.
    title Заголовок окна (для chest). Поддерживает цвета и плейсхолдеры.
    rows Число рядов (только chest, 1–6; вне диапазона обрезается). Для inventory игнорируется.
    commands Список команд, открывающих меню (см. Commands-and-Permissions).
    triggers Легаси-алиас commands (списки объединяются, приводятся к нижнему регистру, дублируются).
    command-description Описание зарегистрированной команды меню (для /help).
    show-in-help Показывать команду меню в /help. По умолчанию true.
    permission Право на открытие меню (на всех путях). Пусто = без ограничения.
    open-requirement Условие открытия меню (см. Requirements).
    items Предметы по слотам (см. Items-and-Clicks). Отдельный элемент может быть input-слотом — ячейкой для вещей игрока.
    update-interval Живое обновление плейсхолдеров открытого меню, тики (см. Advanced-Menu-Options). Несовместимо с input-слотами — на таком меню принудительно 0.
    args Имена аргументов команды открытия → {имя}/{argN}/{args} (см. Advanced-Menu-Options).
    open-item Предмет-открывашка в хотбаре, ПКМ открывает меню (см. Advanced-Menu-Options).
    open-animation Пошаговое появление предметов при открытии, только chest (см. Advanced-Menu-Options).

    type: chest¶

    Сундук-GUI через InvUI (шейдится в плагин, отдельно ставить не надо).

    • rows: 1–6 — число рядов. Итоговый размер сетки = rows × 9 слотов.
    • Слоты нумеруются от 0 до rows*9 - 1, слева-направо, сверху-вниз. Для 3 рядов — слоты 0..26.
    • Заголовок берётся из title, разворачивает плейсхолдеры под конкретного игрока при открытии.
    • Навигация (open_menu/back/refresh) и история переходов работают через MenuService.
    • Только здесь работают input-слоты — ячейки, куда игрок кладёт свои вещи.
    type: chest
title: "<gold>Главное меню"
rows: 6                 # 54 слота (0..53)
items:
  '0': { material: ARROW, name: "<yellow>Назад", clicks: { any: [ { type: back } ] } }

    type: inventory (экспериментально)¶

    Меню рендерится прямо в инвентарь игрока: основные 27 слотов становятся поверхностью меню, а хотбар, крафт и броня остаются обычными.

    Включение — в config.yml:

    inventory-menu:
  enabled: false      # true — показывать меню-инвентарь всем при входе
  default: ""         # id меню (type: inventory), которое показывать по умолчанию

    Ключевые факты:

    • Нумерация слотов в YAML — 0..26, а НЕ 9–35. Физически они ложатся в основные слоты инвентаря (9–35): YAML-слот 0 → слот инвентаря 9, YAML-слот 26 → слот 35. То есть в файле пиши items.0 … items.26, хотя визуально это верхние три ряда инвентаря.
    • rows для inventory-меню игнорируется (всегда 27 ячеек).
    • Меню-по-умолчанию (inventory-menu.default) авто-показывается при входе/респавне — но тихо уважает permission и open-requirement меню (без спама deny-сообщений всем).
    • Переключение между inventory-меню — действием open_menu (см. Actions).

    • Отключить конкретному игроку: /am invclose [игрок] (вернётся при /am open <inv-меню> или перезаходе).

    • input: здесь запрещён. Элемент с input-слотом в type: inventory выбрасывается при загрузке с громким предупреждением в лог: этот бэкенд перерисовывает слоты 9–35 целиком и уничтожил бы вещь игрока. Нужны input-слоты — делай меню type: chest (см. Input-Slots).

    ⚠️ Экспериментально / безопасность: пока меню активно, слоты 9–35 — «только меню»: положить туда вещи нельзя, клики/перетаскивания в этой зоне отменяются. При первом показе любые реальные вещи из этих слотов выпадают игроку (никогда не удаляются). На выходе с сервера пункты меню снимаются, чтобы не попасть в сохранённый инвентарь. Тестируй без ценных вещей.

    ⚠️ Шифт-клик и цифровые клавиши глушатся везде, пока у игрока активно инвентарное меню — не только в зоне 9–35, но и в любом открытом сундуке/эндер-сундуке поверх. Туда же входят двойной клик («собрать всё») и перенос через F. Иначе массовый перенос вытаскивал бы пункты меню из зоны 9–35, а следующая перерисовка печатала бы их заново — бесконечная дупликация. Это возврат к поведению до 1.7.0: если у тебя inventory-menu.enabled: false (по умолчанию), тебя это не касается вообще.

    type: inventory
title: "HUD"            # title для inventory не показывается как заголовок окна
items:
  '0':                  # физически слот 9 инвентаря
    material: COMPASS
    name: "<green>Спавн"
    clicks: { any: [ { type: run_command, command: "spawn" } ] }
  '26':                 # физически слот 35 инвентаря
    material: NETHER_STAR
    name: "<gold>Меню"
    clicks: { any: [ { type: open_menu, menu: main } ] }

    Цвета (title / name / lore)¶

    Форматы можно смешивать в одной строке (util/Text.java). Легаси-коды переписываются в MiniMessage до разбора, поэтому всё работает вперемешку:

    Формат Пример Результат
    Легаси-код &c&lПривет красный жирный
    Hex через &# &#ff8800Привет цвет #ff8800
    Голый hex #ff8800Привет цвет #ff8800
    Bungee/Spigot hex &x&f&f&8&8&0&0Привет цвет #ff8800
    MiniMessage <red>Привет, <gradient:#f00:#00f>Радуга</gradient> как в MiniMessage
    Смешанно &e<bold>Жёлтый жирный</bold> #00ff00зелёный комбинация

    Легаси-коды: &0..&9, &a..&f (регистр не важен) — цвета; &k/&l/&m/&n/&o/&r — обфускация/жирный/зачёркнутый/подчёркнутый/курсив/сброс. &, за которым нет валидного кода, остаётся как есть. У имён и лора предметов курсив по умолчанию выключен (ванильный италик не навязывается).

    Легаси — язык по умолчанию. Все примеры плагина (config.yml, menus/*.yml) написаны &-кодами: их проще читать и они привычны админам. MiniMessage никуда не делся и нужен для того, чего в легаси просто нет — <gradient:…>, <rainbow>, <hover:show_text:'…'>, <click:run_command:'/spawn'>. Обе нотации можно смешивать в одной строке:

    title: "&8» <gradient:#ff5555:#ffaa00>Кузница</gradient>"
lore:
  - "&7Цена: &f1 слиток"
  - "#88ff88Успех: &a60%"

    Разбор устроен так, что #RRGGBB внутри MiniMessage-тега не трогается: <#ff5555>x</#ff5555>, <gradient:#ff5555:#ffaa00> и <click:run_command:'/say #ff0000'> проходят байт в байт. А одиночный <, который тега не открывает (HP < 50 #ff5555), обычному тексту не мешает.

    Полный разбор форматов — на странице Items-and-Clicks и в Placeholders-and-Integrations.
