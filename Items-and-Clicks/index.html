    Предметы и клики¶

    Предметы задаются под ключом items. Ключ = номер слота (число в кавычках), значение = описание предмета.

    • Для chest-меню слоты: 0 .. rows*9-1.
    • Для inventory-меню слоты: 0 .. 26 (ложатся в слоты инвентаря 9–35, см. Menu-Types).

    Ключ, который не парсится как число, пропускается с предупреждением в лог.

    Поля предмета (items.<slot>)¶

    Поле Тип Назначение
    material строка Материал Bukkit (DIAMOND, LIME_DYE, …). Неизвестный/не-предмет → STONE + предупреждение.
    cmd строка Custom-model-data (строка, не число) для кастомной текстуры/модели из ресурспака.
    head-owner строка Только для PLAYER_HEAD: ник владельца головы. %player_name% / {аргумент} → голова смотрящего.
    head-uuid строка Только для PLAYER_HEAD: UUID игрока (с дефисами или без).
    head-texture строка Только для PLAYER_HEAD: кастомный скин — base64-значение textures, URL скина или texture-hash.
    name строка Отображаемое имя. Цвета/плейсхолдеры; курсив по умолчанию выключен.
    lore список строк Описание. Каждая строка — цвета/плейсхолдеры.
    flags список строк Имена ItemFlag для скрытия (напр. HIDE_ATTRIBUTES, HIDE_ENCHANTS). Неизвестные имена пропускаются.
    hide-all bool true — скрыть все item-flags (эквивалент перечисления всех флагов). Имеет приоритет: если true, flags игнорируется.
    animation секция Кадровая анимация предмета: interval, loop, frames. Кадр наследует базовый предмет. Только type: chest, не на input-слоте.
    clicks секция Действия по типу клика (см. ниже).
    view-requirement требование Предмет виден только при выполнении условия (см. Requirements).
    click-requirement требование Гейт клика: не выполнено → deny, иначе → success + действия клика.
    input секция Делает слот input-слотом — ячейкой, куда игрок кладёт свой предмет. Полностью меняет правила элемента, см. ниже.

    Полный пример предмета:

    items:
  '15':
    material: DIAMOND_SWORD
    cmd: "custom_blade"            # строковый custom-model-data
    name: "<red><bold>Меч VIP"
    lore:
      - "<gray>Только для VIP"
      - "<dark_gray>Баланс: <white>%vault_eco_balance%"
    hide-all: true                 # спрятать атрибуты/зачарки/прочий тултип-мусор
    view-requirement:
      type: permission
      permission: alexmenus.vip
    clicks:
      left:
        - type: message
          text: "<red>Взмах!"

    Про cmd (custom-model-data)¶

    Значение — строка (используется строковый компонент CustomModelDataComponent), как в 1.21.11. Ресурспак сопоставляет эту строку своей модели/текстуре. Это НЕ старый целочисленный CMD. Пусто/не задано — предмет остаётся ванильным.

    Головы игроков (кастомный скин)¶

    Для material: PLAYER_HEAD можно задать кастомный скин головы. Заполни одно поле:

    Поле Назначение
    head-texture Текстура: base64-значение textures, URL скина (https://textures.minecraft.net/texture/…) или texture-hash. Оффлайн и мгновенно — рекомендуется для статичных кастомных голов.
    head-uuid UUID игрока (с дефисами или без). Берёт скин онлайн-игрока или из кэша сервера. Поддерживает плейсхолдеры (напр. %player_uuid%).
    head-owner Ник игрока. %player_name% / {аргумент} → голова самого смотрящего. Берёт скин онлайн-игрока или из кэша. 
    items:
  '11':
    material: PLAYER_HEAD
    head-owner: "%player_name%"           # голова смотрящего игрока
    name: "<aqua>Твой профиль"
  '13':
    material: PLAYER_HEAD
    head-texture: "eyJ0ZXh0dXJlcyI6ey..." # base64 — точный кастомный скин, оффлайн
    name: "<gold>Кастомная голова"

    Совместимость с DeluxeMenus. Для миграции конфигов понимаются и префиксы прямо в material: material: basehead-<base64> и material: texture-<base64> → как head-texture; material: head-<ник> → как head-owner.

    Приоритет: head-texture → head-uuid → head-owner. Для произвольных игроков надёжнее всего head-texture (не требует онлайна/кэша и не грузит главный поток). Ключи head-* действуют только на материал PLAYER_HEAD; на других материалах игнорируются.

    Про input — слот для вещей игрока¶

    Если у элемента есть ключ input:, ячейка перестаёт быть кнопкой и отдаётся игроку целиком:

    items:
  '13':
    input:
      accept:
        - material: DIAMOND_SWORD
      placeholder:
        material: GRAY_STAINED_GLASS_PANE
        name: "&7Положи сюда меч"

    На таком элементе не работают:

    • clicks: и click-requirement — кликами по ячейке распоряжается инвентарь, а не меню. Логику вешают на соседнюю кнопку;
    • view-requirement — игнорируется (спрятать слот значило бы спрятать чужой предмет);
    • animation: — запрещена (перерисовка ячейки визуально съела бы вещь игрока), см. Анимации;
    • material: — картинка пустой ячейки берётся из input.placeholder.

    Полное описание — Input-Slots.

    Про flags / hide-all¶

    flags — список имён ItemFlag (регистр не важен, обрезаются пробелы). hide-all: true подставляет все существующие флаги — удобно, чтобы полностью очистить тултип «кнопки». Одно и то же поведение доступно и в give_item (см. Actions).

    Про animation — кадры предмета¶

    Ключ animation: заставляет предмет перебирать кадры, пока меню открыто. Кадр — это переопределения поверх базового предмета: всё, что кадр не упомянул, наследуется, а - {} — это ровно базовый предмет.

    items:
  '13':
    material: LIME_CONCRETE
    name: "&aКнопка"
    animation:
      interval: 5           # тиков на кадр (по умолчанию 10)
      loop: pingpong        # loop | once (false) | pingpong
      frames:
        - {}                        # базовый предмет
        - material: GREEN_CONCRETE  # меняется только материал
        - material: LIME_STAINED_GLASS
    clicks:
      any:
        - type: message
          text: "&aГотово!"

    Минимум 2 кадра; на input-слоте и на type: inventory анимация запрещена (пишется предупреждение в лог, ключ выбрасывается). update-interval для анимаций не нужен.

    Полное описание — Анимации.

    Клики (clicks)¶

    Под clicks каждый ключ — тип клика, значение — список действий (см. Actions). Действия выполняются по порядку.

    clicks:
  left:
    - type: message
      text: "<yellow>Левый клик"
  right:
    - type: sound
      sound: "minecraft:block.note_block.bell"
  any:
    - type: refresh

    Типы клика¶

    Ключ в YAML Алиасы Bukkit-клики, которые сюда попадают
    left — LEFT, WINDOW_BORDER_LEFT
    right — RIGHT, WINDOW_BORDER_RIGHT
    shift_left shiftleft SHIFT_LEFT
    shift_right shiftright SHIFT_RIGHT
    middle — MIDDLE (клик колесом)
    drop q DROP, CONTROL_DROP (клавиша выброса)
    any all любой клик

    Важно про any: действия из any выполняются вдобавок к действиям конкретного типа. Порядок: сначала действия конкретного клика (например left), затем any. То есть any — это «общий хвост» для всех кликов, а не «fallback только когда нет конкретного».

    clicks:
  left:
    - type: message
      text: "Только по ЛКМ"
  any:
    - type: sound             # прозвучит и по ЛКМ, и по любому другому клику
      sound: "minecraft:ui.button.click"

    Клики, которые ни во что не маппятся, считаются UNKNOWN — по ним срабатывает только any.

    Порядок обработки клика¶

    1. Если у предмета есть click-requirement и условие не выполнено → выполняются deny-действия, клик останавливается.
    2. Если условие выполнено → выполняются success-действия (если заданы), затем действия клика (конкретный тип + any).
    3. Предмет со скрытым view-requirement не отрисовывается и клики по нему не срабатывают (в обоих бэкендах пустая ячейка инертна).
    4. Если внутри действий клика есть списание (take_item/take_money/take_exp) и оно не прошло — всё, что стоит после него, не выполняется (см. Actions). То же самое относится к списаниям внутри success: их провал останавливает клик целиком.

    Подробности по условиям — Requirements; по действиям — Actions.
